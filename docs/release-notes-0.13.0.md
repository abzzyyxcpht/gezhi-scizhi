# 格致 SciZhi 0.13.0

2026-10-23

本版完善成果检查与人工复核的完整操作路径。桌面和终端使用同一套后端结果，旧批准不会自动覆盖更新后的材料。未增加模型服务或 Agent 框架依赖。

## 成果与复核

- 识别实际流程生成的 `extract.digest_md` 及规则引用格式化输出，兼容旧摘要记录。
- 检查结果携带 `revision`，覆盖成果内容、任务轮次、当前本地材料哈希和检查规则版本；纯显示缓存及复核记录不改变成果版本。
- 复核必须提交明确的 `approved` 或 `changes_requested`，并携带用户读取的 `expected_revision`。过期提交返回 `stale_revision`，不会覆盖已有记录。
- 同版本明确批准才使人工项通过；要求修改为未通过，版本变化为需重新复核。只有旧格式姓名/说明的记录保留，但不再视为对当前版本的批准。
- 复核存储使用进程内锁、跨进程锁和原子替换，保留最近 50 条历史。读取损坏或写入失败均显式报告，不以空文件替代旧数据。
- 没有可核对路径或材料缺少哈希时，不能用“核对了零份材料”得出通过。

## 桌面

- 返回成果页、切换验收页签或点击「重新检查」时读取当前状态，避免同任务缓存长期显示旧结果。
- 将需处理项放在前面；条件、说明与可展开依据分层展示，依据支持继续展开，中文标签代替内部字段名。
- 保存复核在后台执行，结果不默认选择通过。失败保留输入，回执不确定时提示重新核对，避免重复提交。
- 同一任务保存期间不能打开第二次复核并覆盖决定；旧弹窗关闭事件或迟到回执不能影响新的任务/弹窗。

## 终端

`/checks [任务ID]` 查看清单，`--details` 展开标准与依据。复核必须先读取同一任务的清单：

```text
/checks task01 --details
/checks review task01 --decision approved --by "Jane Doe" --note "已核对材料和引用"
/checks review task01 --decision changes_requested --by "Jane Doe" --note "需要补充来源"
```

每次写入尝试后都要重新读取，不能重复提交同一缓存版本。命令校验任务、引号参数、未知选项和错误回执，展示文本统一脱敏；远程引擎不会把尚未接入的能力列为可用。窄终端按实际页头高度计算转写与滚动空间，保留输入和审批状态。

## 兼容与验证边界

- 版本由 `src/version.py` 定义，终端 package 与 lock 同步为 0.13.0。
- `outcome_checks` 增加字段；`outcome_review` 的写入现在要求显式决定和读取版本。旧客户端必须先读取新清单并补齐这两个字段，省略时会得到错误。
- 自动检查证明记录、材料与流程状态符合所列条件，不证明科研结论真实。真实检索覆盖和模型效果仍取决于材料与所配置服务。
- 验收使用隔离测试数据和真实桌面/终端控件，不调用付费模型，不接触用户研究数据。原生截图入口为 `scripts/capture_desktop.py --screens outcome-checks,outcome-review`。
- 一手研究、采用范围和未采用项见[本轮研究记录](research/2026-10-23-outcome-review-sources.md)。
