# 智能体执行与科研流程改进

本次更新围绕检索失败、会话恢复、长回复阅读和代码复制，沿用共享界面设计系统。

## 文献检索与已有材料

- OpenAlex 和 Crossref 分别记录成功、失败或未启用状态。任一源失败时保留另一源的真实结果，并显示警告；全部启用源失败时明确报错。正常空命中仍与网络失败区分。
- OpenAlex 不可用时跳过依赖它的引用扩展，扩展失败保留已经获得的文献。Crossref 条目不会被当作 OpenAlex 文献 ID 发往引用接口。
- DOI URL、前缀和大小写统一去重，首轮与后续扩展共用规则；无 DOI 的 Crossref 条目可以稳定生成身份。
- 在线失败不再生成演示文献。用户明确提供的本地 PDF 或文本仍可处理，新增材料、保留材料、跳过原因和在线失败分别报告；本地材料不可用时保持已有工作区。
- 缺证据补检区分完成、空命中、失败和跳过。失败保留原综述与证据，重复恢复不自动重复补检。
- 并行任务、模型子任务和审批恢复均传递本轮检索诊断；诊断从实际工具回执读取，不复用继承的旧工作区信息。

OpenAlex 可选认证使用 `GEZHI_OPENALEX_API_KEY` 环境变量，仅通过请求头发送。连接器与系统自检使用同一认证入口；HTTP 状态与错误类型可用于排查，原始密钥不进入查询参数、缓存键或错误日志。接入规则见[官方认证说明](https://help.openalex.org/api/authentication/)。

## 审批与子任务恢复

- 确定性运行时在授予会话权限或执行旧审批前检查持久取消标记。进程重启后批准已取消操作不会再触发工具。
- 子任务审批后完成时只保存自己的产物与状态，避免用另一进程中的旧缓存覆盖父工作区。
- 父会话继续时读取已完成子任务的持久产物。单个子任务沿用既有工作区合并语义；并行文献任务按原请求顺序归并，失败或取消分支不贡献产物。
- 待归并状态与父工作区一起原子保存，已消费标记阻止重复合并。工具回执已落盘但等待状态未保存的崩溃窗口，先恢复回执再决定是否可以继续。
- 全部检索分支失败时保留原文献池；新的失败诊断仍可交给父会话处理。

## 阅读与复制

- 同一事件页内，相邻且属于同一步的流式增量合并后渲染；用户消息、工具事件、步骤切换和最终回复保持原有顺序与边界。
- 旧分页请求的成功或错误响应都检查会话与刷新代次，不覆盖已经切换的新视图。
- 会话代码块、项目源码、差异预览和设置样例提供语言标签与复制入口。复制保留原始缩进和换行，不包含行号；完成剪贴板调用后才显示成功。
- 复制失败可以重试；复制期间内容更新会提示重新复制。审批中的命令复制也等待实际结果，避免提前报告成功。

## 验证范围

验证覆盖取消后的旧审批、子任务审批与重启恢复、有序并行合并、失败产物隔离、重复恢复、来源降级、显式本地材料、归档诊断、流式解析次数和剪贴板成功及失败。外部检索和模型请求使用可控制的测试替身，不使用真实密钥或付费调用。

本地检查包含 Python 全量回归、Ruff、UI 静态检查、TUI 全套和五项离线科研评测。原生桌面检查覆盖 1440×900、1100×760 的代码预览与会话，另检查浅色 20px 界面。离线评测使用合成材料，验证流程与追溯规则，不代表真实科研效果。

远端验收以本次提交的 [GitHub Actions](https://github.com/abzzyyxcpht/gezhi-scizhi/actions/workflows/ci.yml) 结果为准。

本次交付为源码，既有安装包未重新构建。启动方式：`python scripts/gezhi.py desktop` 或 `npm --prefix tui start`。
