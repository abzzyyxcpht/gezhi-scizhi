# 成果验收：确定性检查清单（2026-10-22）

## 为什么要做

上一轮把"思考强度"从一句偏好变成了可核验的三段回执（请求 / 实际发送 / 供应商回报）。同一套原则还剩一个更影响科研判断的缺口：**成果本身能不能被检查**。

此前项目里有三种"看起来完成了"的表述：

- 模型在计划里写"引用已格式化"——这是声明；
- 终端把受阻会话显示成带 ✓ 的"完成"——这是错误标记；
- 两次支持票就把一条论断标成 `verified`（前端显示"已核验"）——这是把赞同票当成独立核验。

三者共同的问题：**没有任何一处指出"凭什么"**。本轮补上的是一条不依赖模型意见的检查链路。

## 判定口径

`src/outcome_checks.py` 只读取任务记录里**已经存在**的事实，给出五档状态：

| 状态 | 含义 |
| --- | --- |
| `satisfied` | 事实被观测到，且每项检查都成立 |
| `failed` | 事实被观测到，但某项检查不成立（产物缺失、字段不全、缺口已登记） |
| `stale` | 材料在记录之后发生变化或已不可访问，原结论不再适用 |
| `pending` | 等待人工复核，尚未记录 |
| `unknown` | 任务记录里根本没有这项事实（例如还没生成研究包清单） |

检查项与依据：

| 检查项 | 依据 | 不成立时 |
| --- | --- | --- |
| 文献池 / 参考文献 / 摘要整理稿 / 综述框架 | 任务产物键是否存在 | `failed` |
| 材料完整性 | 产物中记录的 sha256 与磁盘文件当前哈希比对 | `stale`（内容变了或文件没了） |
| 参考文献完整性 | 条目数量与必要字段 | `failed` |
| 研究包缺口 | `research_package.build_manifest` 记录的 `deficits` | `failed` |
| 人工复核 | 独立的复核记录（复核人 + 结论 + 时间） | `pending` |

几条硬约束：

- **模型不能关闭人工复核项**。复核记录存在独立存储 `data/outcome_reviews.json`，只经用户的显式动作写入，任务产物里任何字段都不能替代它。
- **材料变了就是 `stale`，不是 `satisfied`**。哈希不一致时明确提示"原结论需要复核"，而不是让旧结论继续显示为通过。
- **`unknown` 不是 `satisfied`**。没有研究包清单时，该项是"未知"，不是"通过"；整体判定因此不会是 `all_satisfied`。
- **整体结论只有三档**：`all_satisfied`（全部通过）/ `needs_review`（有失败或过期）/ `incomplete`（还有待确认或未知）。不允许把"部分通过"说成"完成"。

## 接口

| 入口 | 说明 |
| --- | --- |
| `service.outcome_checks(task_id)` | 只读：取任务产物 + 研究包清单 + 复核记录，生成清单与判定 |
| 桥接 `outcome_checks` | `{"cmd": "outcome_checks", "task_id": "..."}`，只读回执 |
| 桥接 `outcome_review` | `{"cmd": "outcome_review", "task_id": "...", "record": {"by": "...", "note": "..."}}` 记录人工复核；不带 `record` 时只读 |

两条命令都不重跑实验、不补全缺失材料、不联系模型。

## 验证

- `tests/test_outcome_checks.py`：纯函数级——产物缺失判 `failed`、哈希一致判 `satisfied`、内容变更与文件消失判 `stale`、无哈希判 `unknown`、引用字段缺失判 `failed`、缺口登记判 `failed`、复核记录不完整判 `pending`、整体判定三档、空清单不报成功、相同输入结果一致。
- `tests/test_outcome_checks_integration.py`：服务层与桥接层——复核前 `pending`、写入复核后 `satisfied`、缺复核人或缺结论被拒、复核记录写在任务产物之外。
- 同轮修正的显示语义（各自独立提交）：
  - TUI 终态映射：`done/completed → ✓ 会话完成`、`blocked → ✗ 已阻止`、`cancelled → ⏹ 已取消`、`failed → ✗ 失败`、`partial → ◐ 部分完成`、`error → ✗ 出错`、`interrupted → ⏹ 已中断`，未收录状态用中性符号，不再一律打勾。
  - 支持票与核验分离：票数只决定"已录入/受反驳"，`verified` 需要独立核验记录，前端文案不再宣称"已核验"。
