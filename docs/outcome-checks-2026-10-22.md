# 成果检查与人工复核

首次实现于 2026-10-22，接口在 0.13.0 更新。检查读取真实任务产物、本地材料与复核记录；不调用模型、不重跑实验、不替代专业判断。

## 判定

| 状态 | 含义 |
| --- | --- |
| `satisfied` | 所列条件得到已有记录支持 |
| `failed` | 条件不满足，或人工要求修改 |
| `stale` | 材料、成果或任务轮次已变化，旧依据需重新核对 |
| `pending` | 缺少有效人工决定，或旧记录未绑定成果版本 |
| `unknown` | 缺少可判断的信息，例如材料没有哈希或问题类型未识别 |

全部项目通过时为 `all_satisfied`；有失败/过期项为 `needs_review`；尚有未知/待确认项为 `incomplete`。空清单为 `unknown`，不得显示成功。

摘要读取实际的 `extract.digest_md`，保留旧 `digest` 兼容。引用检查识别规则格式化器输出的 `text`、`source_id`、`issues`，并兼容旧元数据条目；排版完成不等于来源真实性已被核验。作者、年份、来源缺项与页码/DOI的补全建议分别表达。研究包中的已登记缺口仍须处理。

## 版本与保存

每次检查返回服务端生成的 `checks.revision`，覆盖当前成果、材料当前哈希、任务上下文与检查规则版本。复核记录及显示缓存不参与成果指纹。桌面在进入清单或手动重新检查时读取，终端在执行 `/checks` 时读取。

复核必须说明是谁、判断是什么，并显式选择 `approved` 或 `changes_requested`。保存携带用户已查看的 `expected_revision`；服务端重新计算版本，不一致则返回 `stale_revision`，不写入。

复核存储在 `data/outcome_reviews.json`，独立于任务产物。明确批准且版本相同才关闭人工项；要求修改仍为未通过。旧记录没有版本或明确决定时保留历史，但需要重新复核。记录损坏时显式报错，不当作空数据覆盖。跨进程锁与原子替换保护并发写入，最近 50 条记录可通过读取接口检查。

## 桥接接口

读取清单：

```json
{"cmd":"outcome_checks","task_id":"task01"}
```

保存人工决定，`expected_revision` 必须来自刚查看的清单：

```json
{
  "cmd": "outcome_review",
  "task_id": "task01",
  "record": {
    "by": "复核人",
    "note": "说明核对过的内容和仍需处理的问题",
    "decision": "approved",
    "expected_revision": "检查接口返回的64位成果指纹"
  }
}
```

要求修改使用 `changes_requested`。不带 `record` 时只读复核记录与有限历史。写入成功回执含 `task_id` 和 `review.by/note/decision/revision`，两端核对后才确认保存。无效字段、未知任务、过期版本或存储错误均返回明确错误。

## 用户操作

桌面入口为「文献与成果 → 验收清单」。需处理项排在前面，展开「查看依据」可以读取来源和复核说明。弹窗不预选通过，保存在后台执行；同一任务保存期间不接受另一项决定。读取失败不开放复核，结果不确定时提示重新核对。旧弹窗事件与迟到回执不影响新弹窗或任务。

终端入口：

```text
/checks task01
/checks task01 --details
/checks review task01 --decision changes_requested --by "Jane Doe" --note "需补充出处"
```

提交必须使用最近已展示的同一任务版本；每次写入尝试后需要重新查看。命令仅限本地引擎。终端支持带引号姓名与说明，拒绝未知参数和控制字符，错误文本与证据统一脱敏。

## 验证范围

- 后端：真实产物模式、材料改动、任务重启、旧记录、明确拒绝、版本冲突、损坏文件、原子替换失败与多进程并发。
- 桌面：重新检查、读取失败、默认未选择、后台保存、切任务、关闭重开、迟到关闭事件与不确定回执；真实面板通过桥接写入隔离存储后修改材料并重新检查。
- 终端：真实控制器读写路由、参数解析、错误脱敏、空/异常回执、远程能力提示，以及 28/42/80 列转写、滚动和输入。
