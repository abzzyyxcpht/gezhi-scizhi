# 会话执行计划与完成依据 · 0.11.0

本轮由用户授权重大升级：研究成熟开源智能体，完成实现、验证、推送和发行；新版验收通过后允许删除旧发行物。

## 目标与取舍

把模型执行中的多步骤计划持久化，并将执行项的完成状态关联到真实工具回执。模型准备结束时，检查计划是否闭合。工具成功只能证明调用结果被记录，不能证明论文结论或代码在全部环境下正确。

优先这个缺口：已有上下文整理、并行子任务和断点恢复，继续复制相近功能收益有限。此次不替换运行时、不引入新的 Agent 框架。上游事实与固定版本见 `docs/research/2026-10-19-agent-harness-sources.md`。

## 合同

- 新增 `plan.read` / `plan.update`。更新属于会话元数据写入，只能操作运行时注入的当前会话。现有工具审批、用户 deny、取消与预算继续生效。
- JSONL 中的 `plan_updated` 是事实源；当前回合与版本检查防止旧更新污染新任务。同一工具调用幂等；回滚以实际保留日志为准。
- 最多 12 项，稳定 ID、标题、验收描述、状态和依据。最多一个执行中条目。不能悄悄删除未完项；阻塞或取消须说明原因。
- 执行项完成必须关联本会话、本回合成功且已执行的业务工具回执；计划工具、未知或失败回执、等待中的任务不能作完成依据。推理项显示为模型声明。
- 只对使用新计划工具的回合启用完成检查。首次未闭合时给一次纠正机会，继续消耗原预算；再次尝试结束仍未闭合则记录 `blocked / plan_incomplete`，不伪报 done。无计划旧会话和简单问答保持兼容。
- 每次请求在预算检查之前更新一份有界计划上下文，压缩不删除日志事实。不自动向旧会话扩大冻结工具权限。
- 桌面使用现有会话状态区展示进度和依据；终端提供 `/progress` 与状态概览。同一只读桥接接口供两端读取。
