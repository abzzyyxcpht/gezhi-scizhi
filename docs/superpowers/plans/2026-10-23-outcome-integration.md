# 成果检查与版本复核集成

**目标**：以 0.12.0 为基线，让研究产物、人工复核与双端反馈形成可验证的完整流程。保留现有中性工作台、Python 运行时和 OpenTUI 架构。

## 本轮合同

- 检查真实科研流程生成的 `extract` 摘要，兼容旧 `digest` 记录；无产物不能报通过。
- `outcome_checks` 返回当前成果 `checks.revision`，由实际产物、材料指纹和研究包事实生成。
- 人工复核记录包含 `by`、`note`、`decision`、`expected_revision`；决定必须显式为 `approved` 或 `changes_requested`。
- 保存必须比较用户实际读取的版本；成果变化拒绝旧版本写入。旧记录无版本时需要重审，旧成果复核不能为新成果背书。
- 已批准且版本相同才支持人工项；要求修改显示未通过，材料/产物变化显示需重新复核。保存保留有限历史，避免并发丢失记录。
- 桌面支持手动重查、同任务成果变化失效、读取失败重试及迟到回执隔离。保存复核不阻塞界面，关闭/切换弹窗后不得更新其他任务。
- 终端 `/checks` 接通真实控制器，显式读取后才可提交该版本的复核。结构化错误、脱敏和窄屏显示沿用现有合同；本地能力不冒充远程可用。
- 产品文案直接说明现状、依据和下一步；保留必要边界，去掉重复口号、无意义技术字段和装饰性状态。
- 不读取或改动真实研究数据，不调用付费模型验证；测试和原生截图使用隔离目录。
